# UI feedback round 5 — 2026-07-19 (user list, investigated same day)

Nine items from the user's live use, each verified against master
70e17ae (live browser probe on a sandboxed instance + code trace;
investigation by Opus agent, evidence file:line-anchored). Verdicts:
6 CONFIRMED, 2 NOT-CONFIRMED-but-UX-gap, 1 facts-question answered.

## Items

1. **"Destination cycle (o) doesn't work" — NOT CONFIRMED (works),
   but a real UX gap.** Live probe: `o` cycles correctly on the
   unarmed Detail action bar. It is context-gated three ways with NO
   feedback when gated: (a) an armed bar routes every key to
   disarm/confirm; (b) a pane-proposal bar replaces the action bar
   entirely; (c) a user-scope record's cycle is the single element
   `("claude-md",)` (models.py:94-98) so `o` is inert. A silent no-op
   reads as a dead key. **Fix: feedback on gated/no-op keys** (item
   F5-1): a transient hint ("nothing else to cycle to" / "confirm or
   cancel first").
2. **"Toggle episode brief (b) doesn't work" — NOT CONFIRMED (works),
   same UX gap.** `b` toggles the disclosure live — but the brief
   block only renders when the record body carries `## Episode brief`
   (models.py:1020-1044); on briefless records `b` silently no-ops.
   **Fix (F5-2): transient "no episode brief on this record" hint**
   (rides the same no-op-feedback mechanism as F5-1).
3. **"Escape through the ? overlay cancels an in-progress Iterate" —
   CONFIRMED, the round's severest item.** The overlay is non-modal
   and has no Escape handler; Escape falls through to the keymap `up`
   entry → `goUp()` → `clickAction("interrupt")` when a pane turn is
   in flight (app.js:169-214, 163-167). Worse: the overlay's own text
   promises "any other key dismisses" and only `?` actually does
   (help_overlay.html:14 — an unimplemented promise). **Fix (F5-3):
   overlay-visible → Escape (and per its own text, any key) closes
   the overlay and stops; nothing bubbles to the page keymap.**
4. **"Raw-YAML Change region should be collapsible" — CONFIRMED.**
   The Change section renders always-open (detail.html:70-100); the
   `proposal-yaml` kind duplicates in raw form what the card sections
   above already render humanly. Nuance: `diff` and `hook` kinds are
   genuinely informative. **Fix (F5-4): collapse the `proposal-yaml`
   kind by default behind a disclosure (episode-brief pattern);
   diff/hook kinds stay open** (they are the actual preview).
5. **"No way to accept a change when the dotfiles repo has
   uncommitted changes" — CONFIRMED; RULING REQUIRED.** The dirty
   guard (chezmoi.py:99-116 preflight; gitops.paths_dirty for
   skill/project targets) refuses before any edit; the UI renders the
   stderr verbatim with no path forward; no --force exists anywhere.
   The pin is deliberate (S-10 family: never entangle our commit with
   the user's uncommitted work). Whether and how to add an accept
   path is the user's values call — routed as this round's ruling
   (options: guided commit-the-target-first affordance / explicit
   override ceremony / leave manual).
6. **"Timestamps read like log entries" — CONFIRMED.** Raw ISO-8601
   at: Detail finding line ("created 2026-07-19T19:19:16Z"), miner
   block last-run + per-run ts, follow-ups unblocks-on, report page.
   Humanized precedents already exist (age_days day-counts; "Routed
   Nd ago. Sighted N times since.", models.py:484-490) but there is
   no shared humanizer. **Fix (F5-6): one `humanize_ts` filter
   ("3 days ago" / "just now" with the absolute in a tooltip/title),
   applied at every raw site.**
7. **"After Iterate completes, no sense of what changed" —
   CONFIRMED.** Completion shows transcript + status/$cost/turns
   footer only (pane.html:47-52); FileChanged events silently refresh
   the left column; nothing consolidates what the turn touched.
   **Fix (F5-7): a compact post-run "this turn changed: …" line from
   the drain's already-known FileChanged targets + proposal events.**
8. **"Does the Iterate conversation survive navigation?" — ANSWERED
   (facts):** in-memory only, one live session server-wide, never
   written to disk (proposals slot "never persisted" by design).
   Plain navigation does NOT discard it — returning to the same
   record re-renders the transcript from the snapshot. It IS
   discarded by: any resolution verb on the record (deliberate —
   teardown before git mv/rm), `q` close, the idle monitor's parked
   teardown, and server restart. **Scope decision routed to the
   user:** document/hint the actual lifecycle in the UI (small) vs
   persist transcripts to disk with resume (medium-large feature).
9. **"What is skill-md?" — CONFIRMED labeling gap.** Mechanically:
   compile into the managed section of the skill's existing SKILL.md
   (verbs.py `_resolve_target`; requires skill scope; never creates
   the file). Plain-words glosses already exist in
   `models._GROUP_LABELS` ("Skill doc", "Project instructions",
   "Reference file", "Guard hook", "New skill") but ONLY the Bucket
   group headers use them; the Detail action bar and Why region print
   the raw enum. **Fix (F5-9): reuse `_GROUP_LABELS` on Detail
   ("Destination: Skill doc (skill-md)"), including the Alternates
   line.**
